# Social Context Digest — бриф проєкту

## Навіщо
Дві мети, обидві рівноцінні:
1. **Не вилітати з суспільного контексту** після видалення Instagram з телефона. Я пішов звідти, щоб забрати увагу в алгоритму, тому звіт не має відтворювати стрічку: прочитав за 2 хвилини, закрив.
2. **Навчитись будувати агентів на Claude Code** на живому прикладі: skills, hooks, subagents, MCP, headless, evals.

Інструмент тільки для себе. Без користувачів, авторизації, масштабування. Принцип: make it exist first, make it better later.

## Джерела
| Джерело | Що беремо | Частота | Як |
|---|---|---|---|
| football.ua, тег «Ліверпуль» | список заголовків з посиланнями (4–5 на день) | щодня | RSS (перевірити: є фід саме по тегу чи лише загальний; якщо загальний — фільтр «чи стаття про Ліверпуль» через LLM) |
| Instagram, мої підписки | нові пости | щодня | Apify, офіційний apify/instagram-post-scraper (~$2.30/1000 результатів, безкоштовний план $5/міс) |
| Threads, моя стрічка «Для вас» | що зараз обговорюють + медіа | щодня | Playwright з моїм залогіненим профілем браузера |
| Мультиплекс, Луцьк | нові фільми / прем'єри тижня | щотижня | скрипт по сайту/розкладу |

### Instagram — деталі
- Підписок 271: 50 закритих (пропускаємо), 221 публічний.
- Список вже є: `following.json` (вивантажено з `/api/v1/friendships/<my_id>/following/`, поля username, full_name, is_private тощо).
- Тягнемо **тільки пости, новіші за минулу перевірку**. Інакше бюджет не влізе: 221 × щодня ≈ $15/міс.
- Сторіз не беремо (потрібен логін, ризик бану). Для MVP вистачить постів.
- Перший крок: класифікувати 221 акаунт на групи (друзі/знайомі, заклади Луцька, медіа, блогери, бренди, інше) у JSON.

### Threads — деталі
- Брати дані з мережевих JSON-відповідей (`page.on('response')`), а не з DOM: там текст, автор, медіа в оригіналі.
- Посилання на медіа підписані й тимчасові — качати файл одразу при зборі.
- Ризик: це мій основний акаунт (Threads прив'язаний до Instagram). Один повільний прогін на день, ~100 постів.
- Бот, що гортає від мого імені, впливає на мою стрічку — відомий компроміс.
- Playwright MCP — тільки для розвідки. Щоденний збір — звичайний скрипт без LLM.

## Архітектура
джерело → збір (скрипт, без LLM) → SQLite → «тільки нове» → LLM робить звіт → Telegram

- Збір незалежний від джерела: кожне джерело — окремий модуль з однаковим виходом.
- LLM лише там, де потрібне судження (відбір, підсумок, класифікація), а не там, де кроки однакові.
- Запуск: крон на моєму Mac (домашня IP), `claude -p` для LLM-частини.
- Два ритми: щоденний звіт і щотижневий.

## Доставка
- Telegram-бот (ботів я вже робив).
- Медіа відправляти **файлами**, а не посиланнями на CDN Meta (`sendMediaGroup`, до 10 у альбомі).
- Відкрите питання: формат. Варіанти — коротке повідомлення в Telegram, або 3 рядки + посилання на Telegraph з повним звітом. Якщо звіт не влазить в один екран — можливо, проблема в звіті, а не в каналі.

## Етапи
1. **Каркас на football.ua** (1 вечір): RSS → SQLite → нові статті → Telegram → крон. Без LLM. Вчу: CLAUDE.md, хук (не комітити токен бота), permissions для headless, `claude -p`, обробка збоїв.
2. **Instagram** (2–3 вечори): розвідка на 10 акаунтах через плагін Apify → класифікація 221 → щоденний збір нових постів → перший звіт від LLM. Вчу: MCP, plugins, системний промпт звіту, структурований вивід, вибір моделі, контекст, вартість.
3. **Тиждень використання**: нічого не додаю. Кожен поганий звіт зберігаю разом із транскриптом прогону — це майбутній набір для evals.
4. **Threads**: розвідка через Playwright MCP → скрипт → тематичний підсумок. Вчу: skill «як я хочу бачити звіт», prompt injection (пости незнайомців — це чужий ввід).
5. **Щотижневий звіт**: мультиплекс, згодом події Луцька. Вчу: Batch API, prompt caching, extended thinking для тижневих трендів.
6. **Субагенти** — тільки якщо один агент почне захлинатися: окремий субагент на групу джерел, власні tools для доступу до бази.
